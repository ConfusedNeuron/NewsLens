Project: NewsLens
Build a multi-agent news intelligence pipeline called NewsLens. This is not a news aggregator — it ingests content from multiple sources, processes it through an 8-station assembly line, and delivers quantified impact analysis ("who wins, who loses, by how much") as swipeable cards on a web interface. The core value is turning raw news into structured, data-grounded insight cards personalized to a user's financial profile.
The project documents are already in the repo and contain everything needed:
REPLIT_PROMPT.md — the master build instruction. Read this first and follow it completely. It defines the full project structure, tech stack, every pipeline station with exact specs, all API endpoints, the database schema, the frontend requirements, the sources config, environment variables, and the exact build order to follow.
specs.md — deep technical specification. Contains the full database schema with all SQL, every agent's input/output contract, enrichment API details, classification rule engine logic, quality gate conditions, and non-functional requirements like response time and LLM call limits.
PRD.md — product requirements document. Contains user personas, all feature requirements with acceptance criteria, user flows (first visit, returning user, pipeline background run), domain analysis SOPs for Finance/Tech/Geopolitics/Environment, card layout anatomy, phased roadmap, and open questions.
UI_SPEC.md — complete frontend specification. Contains the full color system with CSS variables, typography choices, every component layout described precisely, Tinder swipe interaction behavior, Reel scroll behavior, filter bar spec, onboarding modal 5-step flow, empty/loading states, responsive breakpoints, animation specs, and the full file structure for the frontend folder.
Follow the build order in REPLIT_PROMPT.md exactly — database schema first, then ingestion agents one at a time, then the pipeline stations in sequence, then the API, then the frontend last. Do not build the frontend until the API is serving real cards. Build each station so it can be run and tested independently before wiring them together in the orchestrator.
