# REPLIT BUILD PROMPT — NewsLens Intelligence Platform

## What You Are Building

A multi-agent news intelligence pipeline called **NewsLens**. It ingests content from curated sources, processes it through a structured assembly line of agents, and delivers quantified impact analysis as swipeable cards on a web interface.

This is NOT a simple news aggregator. The core value is:
> "What happened → What the numbers say → Who wins, who loses, by how much → How it affects YOU."

---

## Tech Stack

- **Backend**: Python 3.11+
- **Task Scheduling**: APScheduler (cron-style agent runs)
- **Database**: SQLite (dev) → PostgreSQL-ready schema
- **LLM**: Anthropic Claude API (claude-sonnet-4-20250514)
- **Embeddings**: `sentence-transformers` (local, free — for dedup)
- **Web Framework**: FastAPI
- **Frontend**: Vanilla JS + HTML/CSS (no React needed for MVP)
- **Data APIs**: Yahoo Finance (`yfinance`), FRED API, Reddit PRAW
- **Feed Parsing**: `feedparser`, `beautifulsoup4`, `requests`
- **Email**: Gmail API via `google-auth-oauthlib`
- **YouTube**: `youtube-transcript-api`

## The Pipeline — Station by Station

### Station 1: INGEST (No LLM)
Each ingest agent runs on a schedule and outputs raw items to the `raw_items` table.

**RSS Agent** — reads from `config/sources.yaml`, fetches all RSS feeds, stores title + body + url + source_name + timestamp.

**Reddit Agent** — uses PRAW. Fetches top posts from configured subreddits (score threshold: >50). Stores post title + body + top comment text.

**Gmail Agent** — Gmail API with OAuth2. Reads from configured sender labels/filters. Extracts email body as plain text.

**YouTube Agent** — `youtube-transcript-api`. Given a channel ID or video URL, fetches transcript. Concatenates into readable text.

**Substack Agent** — Each Substack publication has an RSS feed at `/feed`. Treat like RSS.

All agents write to: `raw_items(id, source_type, source_name, url, raw_text, metadata_json, ingested_at, status)`

---

### Station 2: CLEAN (No LLM)
`clean_agent.py` runs after ingestion.
- Strip HTML with BeautifulSoup
- Remove boilerplate (nav, footers, cookie banners) using common selectors
- Detect language with `langdetect` — keep `en` and `hi` only
- Deduplicate using `sentence-transformers` cosine similarity (threshold: 0.85)
- Normalize whitespace, encoding
- Output to `clean_items` table with `clean_text` field

---

### Station 3: EXTRACT (LLM Call #1)
`extract_agent.py` — one LLM call per clean item.

Use prompt from `prompts/extract.txt`. Output must be strict JSON:

```json
{
  "headline": "one sentence",
  "entities": {
    "companies": ["Reliance", "Apple"],
    "people": ["Jerome Powell"],
    "countries": ["India", "USA"],
    "organizations": ["RBI", "Fed"]
  },
  "event_type": "monetary_policy | earnings | regulation | conflict | discovery | market_move | policy | other",
  "numbers_mentioned": ["repo rate 6.5%", "inflation 4.2%"],
  "geography_primary": "India | USA | China | Global | Continental",
  "sector": ["Finance", "Tech", "Geopolitics", "Environment"],
  "time_horizon": "immediate | short_term | long_term",
  "source_credibility": "high | medium | low",
  "confidence": "high | medium | low"
}
```

Store in `extracted_items` table.

---

### Station 4: CLASSIFY (No LLM — Rule Engine)
`classify_agent.py` — deterministic rules on extracted JSON.

Rules engine assigns tags:
- Domain tags: Finance, Tech, Geopolitics, Environment
- Geography tags: India, USA, China, Global, Continental (Africa, Europe, SEA, etc.)
- Importance score: weighted by source_credibility + entity count + number of sectors affected
- Cross-domain flag: if `len(sector) > 1` → mark as cross-domain event

Filter out items below importance threshold (configurable in settings.py).

---

### Station 5: ENRICH (No LLM — API calls)
`enrich_agent.py` — attach real numbers to extracted entities.

For each company in `entities.companies`:
- Fetch stock price + 1d % change via `yfinance`
- Fetch market cap

For each country in `entities.countries`:
- Fetch latest inflation rate, GDP growth, interest rate via FRED API or World Bank API

For commodities if mentioned:
- Crude oil, Gold, Silver via `yfinance` tickers

Store enrichment JSON alongside extracted item.

---

### Station 6: ANALYZE (LLM Call #2 — Core Value)
`analyze_agent.py` — uses prompt from `prompts/analyze.txt`.

Input to LLM:
- Clean text summary
- Extracted JSON
- Enrichment data
- Domain SOP from `config/sop.yaml`
- User profile (if available)

Output JSON:
```json
{
  "summary_60w": "...",
  "what_happened": "...",
  "key_number": "6.5% repo rate held",
  "winners": [{"who": "Home loan borrowers", "why": "EMIs unchanged", "magnitude": "~9Cr people"}],
  "losers": [{"who": "Fixed deposit savers", "why": "Rates not rising", "magnitude": "Opportunity cost ~0.3% annualized"}],
  "india_angle": "...",
  "usa_angle": "...",
  "china_angle": "...",
  "personal_impact": "...",
  "confidence": "high | medium | low",
  "time_horizon": "immediate | short | long"
}
```

---

### Station 7: FORMAT (No LLM)
`format_agent.py` — maps analyze output to card schema.

Card schema:
```json
{
  "card_id": "uuid",
  "headline": "...",
  "summary": "...",
  "key_number": "...",
  "winner": "...",
  "loser": "...",
  "personal_impact": "...",
  "domain_tags": [],
  "geo_tags": [],
  "confidence_badge": "high | medium | low",
  "source_name": "...",
  "source_url": "...",
  "created_at": "...",
  "formats": ["reel", "tinder", "nerd"]
}
```

Write to `cards` table. This is what the frontend API serves.

---

### Station 8: QUALITY GATE
`quality_gate.py` — rule-based filter before cards go live.

Auto-discard if:
- `confidence == low` AND `numbers_mentioned` is empty
- `summary_60w` is under 20 words
- No winners or losers identified

Hold for review if:
- Cross-domain AND confidence == medium
- personal_impact is empty

## API Endpoints (FastAPI)

```
GET  /api/cards              → paginated card feed (filtered by domain/geo)
GET  /api/cards/{id}         → single card detail
POST /api/user/profile       → save user profile
GET  /api/user/feed          → personalized card feed
POST /api/cards/{id}/swipe   → record left/right swipe (relevance feedback)
GET  /api/sources/status     → ingestion agent health check
POST /api/pipeline/run       → manually trigger pipeline (dev use)
```

## Frontend (MVP)

Three views on one page:

**View 1 — Tinder Mode**: Centered card, left/right swipe buttons, keyboard arrow support. Shows headline, summary, key number, winner/loser chips, confidence badge.

**View 2 — Reel Mode**: Vertical scroll, auto-snap to card, swipe up = next.

**View 3 — Nerd Mode** (stub only, locked UI): Two-column layout with source panel + analysis panel. Show as "coming soon" with a lock icon.

Domain filter tabs at top: All | Finance | Tech | Geopolitics | Environment
Geo filter: Global | India | USA | China

## User Onboarding Flow

5-question modal on first visit:
1. Income type (Salaried / Business / Investor / Student)
2. Sector exposure (multi-select checkboxes)
3. Investment profile (FD / Equity / Crypto / None)
4. City (dropdown — major Indian cities + "Other")
5. Companies you care about (free text, comma-separated)

Store in localStorage and send to `/api/user/profile`.

## Build Order for Replit

Build and test in this strict order. Do not move to next until current works:

1. `db/schema.sql` + `db/database.py` — get the schema right first
2. `agents/ingest/rss_agent.py` — simplest ingestion, verify data lands in DB
3. `agents/clean_agent.py` — verify clean output looks right
4. `agents/extract_agent.py` — test LLM extraction with 3 sample articles
5. `agents/classify_agent.py` — verify tags are being assigned correctly
6. `agents/enrich_agent.py` — verify Yahoo Finance + FRED calls work
7. `agents/analyze_agent.py` — test full analysis with enriched data
8. `agents/format_agent.py` + `pipeline/quality_gate.py`
9. `pipeline/orchestrator.py` — wire all agents together
10. `api/main.py` + routes — serve cards via API
11. `frontend/` — build UI last, once API is confirmed working
12. Add remaining ingest agents (Reddit, Gmail, YouTube) one at a time

---

## Key Constraints

- Never call LLM in Station 1, 2, 4, 5, 7, 8. LLM only in Station 3 (extract) and Station 6 (analyze).
- Always validate LLM output is valid JSON before writing to DB. If invalid, retry once, then discard.
- Rate limit LLM calls: max 10 concurrent, add 0.5s delay between calls.
- All agents must be independently runnable for testing.
- Log every pipeline step with timestamp and status to `pipeline_runs` table.
