# NewsLens — Full Project Review (2026-07-26)

Two independent passes: this one, plus a Fable subagent audit run in parallel. Where they disagree it's flagged. All claims re-verified against the live tree and the SQLite DB, not against prior audit docs.

---

## 1. Executive verdict

The engineering is better than the project's own audits give it credit for. The **cards it produces are genuinely good** — readable, India-anchored, winners/losers populated on 41/41. That is the hard part and it works.

Three things are true at the same time:

1. **The product's output is real and decent.** Not mocked, not seeded, not vapour.
2. **The two headline differentiators are dead in the data.** `personal_impact` is empty on 41/41 cards. Structured market data reaches the card as *prose* the user can't verify, not as a field.
3. **The project has been frozen for 63 days** — last code change 24 May, and everything since is documentation. There are now ~2,100 lines of planning markdown + two HTML reports against ~3,300 lines of Python and **zero tests**.

The bottleneck is not technical difficulty. Every remaining blocker is a half-day fix that has been correctly identified in writing, repeatedly, and not done.

## 3. What is stubbed, fake, or broken

### Personalization — broken at three independent layers
- `analyze_agent.py:220` calls `analyze_item(client, enriched, sop)`. The `user_profile` parameter is accepted at `:95` and **never passed**. Prompt receives "Not provided"; `prompts/analyze.txt` then mandates an empty string.
- `prompts/personal_impact.txt` exists and is **read by no code**.
- Profile save 405s: `openapi.yaml:132` declares `put:` → generated client sends `method: "PUT"` (`api.ts:484`); backend registers `@router.post("/user/profile")` only (`api/routes/user.py:19`). Error is silently swallowed in `feed.tsx`.
- `user_profiles` table: **0 rows, ever.**

### Enrichment — surfaces as unverifiable prose, not data
Only **2 of 40** enriched items got any stock data (the hardcoded `COMPANY_TICKER_MAP` in `settings.py` almost never matches); all 40 got the same generic commodity blob. `format_agent.py` maps **zero** enrichment fields onto the card, and `cards` has no market-data column.

But it *does* leak into the text — one card's `india_angle` reads *"The USD/INR at 95.68 shows…"*. So the numbers reach the reader as un-badged, un-attributable prose. That's the worst of both worlds: no verification affordance, full credibility exposure.

### The orchestrator has never produced a card
`pipeline_runs` has exactly 10 rows, all from **2026-05-13**, and every LLM stage reads zero: `extract=0, classify=0, enrich=0, analyze=0, format=0, quality_gate=0`. The 26 real cards were created 2026-05-24 with **no `pipeline_runs` rows at all** — they came from running agents by hand. "The pipeline works end-to-end" is unproven.

### Dedup — worse than previously documented
`clean_agent.py:33-36` uses module-level in-memory lists; state resets every restart and `clean_items.dedup_hash` is never read back. **Additionally**, `is_duplicate()` returns at `:93-94` when sentence-transformers is missing — *before* the hash is appended at `:103-104`. So without that optional dependency, even exact-hash dedup records nothing. Silent no-op.

### Other confirmed
- **"hold" is a black hole with two live occupants.** `quality_gate.py:55-56` can return `"hold"`, but there's no status column, review route, or UI. Two cards sit at `is_live=0` since 24 May, re-evaluated identically forever.
- **Fabricated seed news served as live.** `db/seed.py:368-380` inserts 15 invented stories ("Nifty 50 Crosses 27,000", "GST Collections Cross ₹2 Lakh Crore") with `is_live=TRUE`, no `is_seed` flag, indistinguishable via `/cards`.
- **Dead sources unnoticed.** Reuters (`feeds.reuters.com` — discontinued years ago) and Down To Earth returned 0 items. Reddit credentials never set.
- **~50% extraction failure**: `clean_items` = 42 extracted vs 50 failed.
- **Fake telemetry**: `log_stage` writes `started_at == completed_at` (`orchestrator.py:24-26`), so all durations are fiction.
- **Honest stubs**: Gmail/YouTube return 0; Nerd Mode 501; `/saved` a placeholder while `swipe_events` is written but never read anywhere (0 rows regardless).
- **Dead scaffolds**: `artifacts/api-server/` (Express boilerplate), `lib/db/` (Drizzle schema is literally `export {}`), `artifacts/mockup-sandbox/`, Gemini remnants in `requirements.txt` and `settings.py:70-73`.

## 4. Design critique

### The good design decision
**Two LLM calls per article, deterministic Python everywhere else.** Classify, enrich, format and the quality gate are all rules-based; the model is used only where language understanding is actually required. This keeps cost near zero at personal scale and makes 6 of 8 stations debuggable and testable. Keep this. It's the best call in the project.

The staged tables (`raw → clean → extracted → classified → enriched → cards`) are the second-best call — each stage is inspectable and the `status='pending'` convention gives you resumability for free.

### The dangerous design decision — nobody has flagged this
`prompts/analyze.txt` says:

> "magnitude must contain a number or estimate — not 'significant' or 'substantial'."
> "Anchor all numbers to the enrichment data. **If the data is unavailable, use 'est.' prefix.**"

That second clause **licenses the model to invent quantities**. And it does. From real output:

- *"Est. 20 million barrels per day of oil transit secured"*
- *"est. $3 trillion in disputed maritime area resources"*
- *"est. tens of millions in revenue"*

None of these come from the enrichment payload. They are LLM priors wearing an "est." fig leaf. For a product whose entire pitch is *quantified, trustworthy impact*, the prompt is a hallucination generator with a disclaimer. Combined with (a) enrichment only hitting 2/40 items and (b) no financial disclaimer on any card, this is the single biggest product risk in the repo — larger than any bug listed above, and it appears in **none** of the three prior audits.

**Fix:** make `magnitude` nullable. Instruct: use a number *only if it appears in `enrichment_json` or `extracted.numbers_mentioned`*; otherwise return `null` and let the UI render "magnitude not quantifiable." A card that admits it can't quantify is worth more, in this product, than a card that guesses.

### Garbage in, garbage quantified
RSS items carry title + a ~50-word snippet. That's all `extract_agent` ever sees, which is why `numbers_mentioned` is usually empty, why extraction fails ~50% of the time, and why the model resorts to inventing magnitudes. `DATA_SOURCES_STRATEGY.md` is right that full-text fetching (`trafilatura`) is worth more than every other improvement combined — it's upstream of the hallucination problem too.

### The importance score is weighted wrong
`classify_agent.py:38-43`:

```
score = cred_weight * 0.4 + min(companies,5) * 0.02 + min(sectors,4) * 0.2 + cross_domain * 0.3
```

Sector count contributes up to **0.8**; source credibility spans only **0.12 → 0.4**. A low-credibility item tagged with four sectors outranks a high-credibility single-sector item every time. In a product built on trust, the credibility signal is the weakest term in its own ranking function. The prior audit noted the company weight deviating from spec (0.02 vs 0.1); the structural imbalance is the bigger issue.

### Personalization architecture is undecided, not merely unimplemented
Even after passing `user_profile` into `analyze_item`, the design bakes one user's profile into a globally-shared card. That cannot scale past a single user. The correct shape — a cheap read-time or nightly re-personalization pass using the currently-dead `personal_impact.txt` prompt — is *named* in `AUDIT_2026-07-05.md` but never decided. **This is the most important unwritten decision in the project.** Write it down before writing code.

### Security & ops
- Live `nvapi-` key in plaintext `.env` since 24 May. Verified never committed and now `.gitignore`d — but the July 5 audit demanded rotation and it still hasn't happened, 21 days later.
- `POST /api/pipeline/run` is unauthenticated and unthrottled (`sources.py:66-76`). Two concurrent calls both read `status='pending'` without claiming rows → duplicate LLM spend and duplicate cards. APScheduler's `max_instances=1` doesn't cover the HTTP path.
- CORS `allow_origins=["*"]` + `allow_credentials=True` (`api/main.py:32-35`) is an invalid combination browsers reject.
- Git: two commits, both titled *"Initial NewsLens project — Tasks #1-#5 baseline"*, and the only working LLM code (`llm_client.py`, rewritten agents, `settings.py`) exists **only as uncommitted working-tree changes**. One bad `git checkout` from losing it.

### Provider identity confusion
`llm_client.py`'s docstring says the active model is "DeepSeek V4 Pro" via CommandCode; `settings.py:48` actually sets `deepseek-ai/deepseek-v4-flash` on NVIDIA NIM; `.env.example` says the base URL defaults to OpenRouter; the env var is named `COMMANDCODE_API_KEY` but holds an `nvapi-` key. Four stories, one variable.

## 5. Good / Bad / Ugly

**Good**
- Cards are genuinely readable and useful. The hard part works.
- 2-call-per-article cost architecture; deterministic Python for everything else.
- Staged, inspectable schema with free resumability.
- Input-validation layer that refuses to spend money on garbage (`llm_client.py:260` — skipping low-confidence numberless extractions is a smart, spend-aware rule).
- Typed OpenAPI → orval client discipline.
- Polished, accessible frontend — better than most student projects.
- Unusually honest self-audits. `AUDIT_2026-07-05.md` is accurate; I re-verified all five headline claims and all five still hold.

**Bad**
- Both differentiators dead: `personal_impact` 0/41; enrichment 2/40 and never a typed field.
- Profile save 405s on every attempt, error silently swallowed.
- Dedup is a silent no-op without an optional dependency.
- Snippet-only inputs → ~50% extraction failure.
- Dead Reuters and Down To Earth feeds unnoticed for 2½ months; Reddit never configured.
- Sequential LLM loops with `time.sleep` per item.
- `time_horizon` exists on `extracted_items` and nowhere downstream; hardcoded `"⏱ Near-term"` in the UI. Even the enum vocabulary differs between stages (`short_term/long_term` vs `short/long`).
- Zero tests, zero CI. Every bug above is a bug a 20-line integration test would have caught.

**Ugly**
- **The prompt licenses fabricated numbers in a product whose thesis is verified numbers.** Real cards ship phrases like *"est. $3 trillion in disputed maritime area resources"* with no disclaimer anywhere.
- **63 days, zero code changes, five new planning documents.** The failure mode is documented avoidance, not technical difficulty. ~2,100 lines of markdown + two HTML reports vs 3,300 lines of Python and 0 tests.
- A live API key unrotated three weeks after the project's own audit flagged it as urgent.
- The only working LLM code is uncommitted, sitting on top of a baseline committed twice with the same message.
- 15 invented news stories served as `is_live` cards, indistinguishable from real ones, in a trust product.
- `user_profiles`: 0 rows. `swipe_events`: 0 rows. **The product has no user — including its builder.**

## 7. Where the two audit passes disagreed

The Fable subagent and this pass agreed on nearly everything. Two differences worth recording:

- Fable characterised the cards as evidence the pipeline "worked once." I'd put it more strongly: **the card output is the project's biggest asset** and is being undersold by its own documentation. The dead differentiators are real, but the core analysis engine produces something worth shipping.
- Neither the Fable pass nor any of the three prior audits flagged the **"est." hallucination licence in `prompts/analyze.txt`**. I rate it the highest-severity finding in the repo — it's the one defect that damages the product's actual value proposition rather than a feature's completeness.
